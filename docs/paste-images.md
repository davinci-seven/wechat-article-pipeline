# 粘贴到公众号时，图片会怎样

一键粘贴模式要把文章放进 `mp.weixin.qq.com` 的图文编辑器。文字和内联样式可以过去，**本地图片过不去**。所以预览里照常显示图片，复制出去的正文改成编号占位，并把原图按顺序导出到 HTML 旁边。

## 结论

| 图片从哪来 | 粘贴进公众号编辑器 | 本工具怎么做 |
| --- | --- | --- |
| 已经是公网 `http` / `https` 地址 | 编辑器会尝试自己下载，再存进公众号素材库。对方服务器要能被微信访问，国内图床比较稳，GitHub 上的文件经常失败。成功后图片通常会被压缩 | 原样保留这个地址，预览和复制稿都用它 |
| 电脑上的本地文件 | 过不去。`file://` 和相对路径微信的服务器拿不到 | 复制稿里写成 `【插图1：01-setup.png】`，原图导出为 `images/01-setup.png` |
| `data:image/...;base64,...` | 不可靠。编辑器不把 data URI 当成要转存的图片，大段 base64 还可能让正文超限、保存失败 | 只用在预览里，让这一个 HTML 打开就能看到图。复制稿里不放 |

朋友要做的事：点「一键复制到公众号」，到后台新建图文后粘贴，再按【插图1】【插图2】从 `images` 文件夹插入，插好后删掉那几行提示。

## 依据

这些行为对得上微信编辑器和常用排版工具的公开说明，本仓库没有登录公众号后台再实贴一次。

- 微信开放社区里，从 Word 带过来的本地图片不能直接进图文，需要先上传；网上的图片一般可以跟着复制走。见[这条讨论](https://developers.weixin.qq.com/community/develop/doc/000e8aed7a02107bb60d8775b51400)。
- [doocs/md](https://github.com/doocs/md) 的使用方式是：正文里放公网图片地址，复制渲染结果，公众号编辑器再把外链图片上传到自己的素材库。GitHub 上的文件经常提示上传失败，国内可访问的地址才比较稳。图片会被重新压缩。见议题 [doocs/md#10](https://github.com/doocs/md/issues/10) 和讨论 [doocs/md#532](https://github.com/doocs/md/discussions/532)。
- 单独复制一张图片（剪贴板里是图片文件，不是 HTML）时，编辑器可以上传。一次复制整篇文章时，剪贴板里是 HTML，图片只是 `<img src>`。本地路径和 data URI 都不是微信服务器能下载的地址，所以插不进对应位置。浏览器也不能在一段 HTML 里按位置附上多张图片文件。

因此不做「把 base64 塞进复制稿，赌编辑器能认」的方案。预览可以看图，粘贴后的位置用编号写清楚，原图放在旁边，比图片悄悄丢了更适合不改代码的人。

## 和完整流水线的差别

`render_wechat.py` 仍会生成「发布稳定版」，把本地图片嵌成 data URI，方便离线预览、不依赖本机路径。那份文件不是一键粘贴模式的复制内容。一键粘贴模式的按钮只复制带占位符的正文。
